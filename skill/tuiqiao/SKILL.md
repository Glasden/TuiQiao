# 推敲

你在这局游戏里身兼两职：**出题人**（写谜面与谜底）和**评点人**（玩家交卷后品评）。玩家看得到谜面，看不到谜底，直到他在网页上点「揭晓原作」。

CLI 的调用方式：\`__TUIQIAO_CLI__\`（下文简写为 \`tuiqiao\`）。stdout 是结果，日志在 stderr；exit 0 成功，1 业务失败，2 用法错误，3 等待超时。

## 最要紧的一条：别剧透

谜底一旦出现在对话里，这局就废了。从创作到玩家揭晓之前：

- **不要**在回复里写出诗、挖空、句意、意象、创作手记中的任何内容，也不要复述、预告或暗示。
- 工具调用的参数在多数 harness 里对玩家可见。**如果你能派子代理，就把「创作」和「建局」两步整个交给子代理**：把题目、取向、体裁、韵书和本文件的路径交给它，要求它**只**回报 \`create\` 输出里的 \`id\`、\`url\`、\`title\`，不得带回诗与其它谜底内容。这样连你自己在评点之前也不知道谜底。
- 不能派子代理时，就自己做，但把诗和对局文件只写进文件（不要用 \`cat\` / \`echo\` 把内容打回对话），建局时带 \`--rm\` 让 CLI 用完即删，并提醒玩家一句「别展开我刚才的工具调用，谜底在里面」。
- 评点写给尚未揭晓的玩家看：可以评他填的字，但不要写出原作里他没填中的字句，说「此处原作另有安排，揭晓后可对照」即可。

## 第一步　问清题目

需要四样东西；玩家已经说明白的就不要再问，其余的**一次问完**（harness 有提问工具就用它，没有就用一条消息列出选项）：

1. **人与事**：一个或几个人物、事件。玩家通常已在开场时给出。
2. **取向**：依史实来写（\`history\`），还是让人与事走向别处（\`alternate\`）。若选后者，问一句想往哪个方向改，或由你定。玩家的话里已有明确指向（「假如……」「如果当年……」「就按历史来」）时跳过。
3. **体裁**：先运行 \`tuiqiao forms --sample 4\` 取四个随机的常用体裁作选项（每次都重新取，不要凭记忆列），并允许玩家自己报一个。谱库收了四种近体诗和八百余个词牌、曲牌；库里没有的体裁也能玩，只是没有格律提示。
4. **韵书**：推荐**中华新韵**（\`xinyun\`，依普通话读音，玩家凭语感就能判断平仄）；也提供**古韵**（\`guyun\`，诗依平水韵、词依词林正韵，保留入声，适合熟悉旧韵的玩家）。简短说明两者的区别，把新韵放在第一位并标明是推荐。

## 第二步　创作（不出现在对话里）

**先写诗，再写故事。** 顺序不能反：故事是为这首诗量身布置的线索。

### 诗

1. 运行 \`tuiqiao form <体裁>\` 看谱：每字的平仄（平 / 仄 / 中，中即可平可仄）与韵位。词牌有多个变体时，照第一个（正体）写，除非你有把握用别的。
2. 写诗。要言之有物：扣住人与事，有具体的意象与转折，忌空泛的套话。改写取向时，诗要落在改写后的结局上。
3. 把诗存成文件，运行 \`tuiqiao check --form <体裁> --rhymebook <韵书> <文件>\`。报告会逐条指出哪一句第几个字平仄不合、哪个韵脚出韵。照着改，再查，**直到零错误**。新韵下注意：旧入声字（白、国、一、石、竹……）按今音读，常是平声。
4. **换字之前先查表，不要凭记忆判平仄**——改东坏西多半出在这里：
   - \`tuiqiao char <几个候选字连写> --rhymebook <韵书>\`：一次查出每个字的平仄、声与韵部（古韵下同时给出平水韵与词林正韵；诗看平水，词看词林）。古韵的入声字（白、月、石、客……）尤其要查。
   - \`tuiqiao rhymes <韵部> --rhymebook <韵书> [--kind ci] [--tone 平|仄]\`：列出某韵的常用字，换韵脚、找同韵字时用。韵部名取自 \`check\` 报告的「韵脚」一行或 \`char\` 的输出；填词用古韵时带 \`--kind ci\`。不给韵部则列出全部韵名。
   - 候选字都查过、确认合律再写回文件，然后重跑 \`check\`。
5. 至多改四轮。仍有错误时，保留最好的一版，建局时加 \`--allow-flaws\`（瑕疵会在揭晓页如实标出）。提醒（△）不必清零。

### 故事（谜面）

三百到五百字的散文，像一则笔记小说或史传片段，以空行分段。它必须让谜底**可推**：

- 诗里每一个要紧的意象、动作、时令、地点，故事里都要有着落，但换一种说法——故事写「江上起了东南风」，诗里才用「东风」；不要让被挖掉的词原样出现在故事里，那就成了找字游戏。
- 写完后自查：只读故事和没被挖掉的字，一位懂诗的读者能不能把每个空填到八九不离十？填不出的空，要么给故事添线索，要么换一处挖。
- 不要在故事里引用或化用整句诗，不要提到「这首诗」。

### 挖空与提示

- \`cloze\`（填字档，择字、辨字两档也用它）：把诗原样抄一遍，用【】括起要挖的字。挖全篇的两到三成，每句至少一处；优先挖诗眼、意象词、动词和韵脚，不挖无从推断的虚字。可以连挖两个字成一个词。
- \`decoys\`（辨字档）：一串干扰字，会和挖去的字一起洗进字盘，让玩家辨。为每处要紧的空备一个「差一点就对」的字——你炼字时掂量过又放下的那个最好，正如「敲」之于「推」：放回原句读得通、平仄也合，只是不如原字贴故事。数量约为空格数的一半，至多 12 个；不能是被挖去的字本身。要和 \`cloze\` 一起给，否则你不知道哪些字会被挖。
- \`hiddenLines\`（补句档）：要整句藏起的句号（从 1 起，按谱面的句，\`check\` 报告里每行开头的数字就是）。选故事里线索最足的句子，约占一半，不要全藏。
- \`glosses\`：逐句的白话大意，条数等于句数。这是玩家可以讨要的提示，所以**只说意思，不出现原句里的字眼**。
- \`imagery\`：三到六个原作用到的意象或关键词，由浅入深排列（玩家一次讨一个，先给最不泄底的）。
- \`note\`：创作手记，揭晓后展示。说说这首诗如何从人与事生发、故事里埋了哪些线索、哪个字你斟酌过。二三百字。

### 对局文件

~~~json
{
  "title": "诗题",
  "subjects": ["玩家给的人", "玩家给的事"],
  "premise": "history",
  "premiseNote": "改写取向时填：往哪个方向改",
  "form": "七绝",
  "rhymebook": "xinyun",
  "story": "谜面。\n\n以空行分段。",
  "poem": "带标点的全诗，\n词以空行分阕。",
  "cloze": "与 poem 完全相同，只是把要挖的字用【】括起。",
  "decoys": "干扰字连写成一串",
  "hiddenLines": [2, 4],
  "glosses": ["第一句的大意", "第二句的大意"],
  "imagery": ["意象一", "意象二", "意象三"],
  "note": "创作手记。"
}
~~~

前八项里除 \`premiseNote\` 外都必填；\`cloze\`、\`hiddenLines\` 不给时 CLI 会自动挑，但远不如你挑的好；\`decoys\` 不给时会从韵表里取同韵同调的字充数，玩家一眼就能排除，辨字档便形同虚设。

## 第三步　建局

~~~
tuiqiao create <对局文件> --rm
~~~

- 成功时输出 \`{ "ok": true, "id": "...", "url": "http://127.0.0.1:7117/g/...", ... }\`，本地服务没起会自动起，之后一直在后台。
- 失败时输出 \`{ "ok": false, "errors": [...] }\`，照 \`errors\` 改文件再建。格律有错而你已尽力时加 \`--allow-flaws\`。
- 玩家不在本机（远程终端、容器、云端环境）时，\`127.0.0.1\` 他打不开：用 harness 提供的预览或端口转发把该端口暴露出去，把转发后的地址给他；需要时用环境变量 \`TUIQIAO_HOST=0.0.0.0\`、\`TUIQIAO_PUBLIC_URL=<对外地址>\` 重新 \`tuiqiao stop\` 再 \`tuiqiao start\`。

然后告诉玩家：题已出好，给出链接，说明网页上有两大档、各三小档：「选字」（择字、辨字、拆篇）从字盘里拣字，不用打字，初次玩不妨从择字起；「落笔」（填字、补句、自赋）要自己写。交卷后回来说一声。**只给链接和一两句引子，不要贴故事全文，更不要提诗。**

## 第四步　等交卷

~~~
tuiqiao wait <id> --timeout <秒>
~~~

把超时设得略低于 harness 对单条命令的时限（缺省 540 秒）。玩家交卷即返回结果；exit 3 表示超时仍未交卷——这时不要循环重试，结束本轮，告诉玩家交卷后回来说一声。玩家回来时运行 \`tuiqiao result <id>\` 取结果（\`status\` 为 \`new\` / \`playing\` 说明他还没交）。

结果里有：\`mode\`（ze 择字 / bian 辨字 / chai 拆篇 / zi 填字 / ju 补句 / fu 自赋）、\`original\`（原作）、\`player\`（玩家版本，未填处为 □）、\`diffs\`（与原作不同的格及其反馈）、\`score\`、\`checks\`、\`hints\`、\`prosody\`（玩家版本的格律问题）。

## 第五步　评点

写一个评点文件，运行 \`tuiqiao review <id> <文件>\`，网页会立刻显示。

~~~json
{
  "grade": "上中",
  "comment": "总评。纯文本，空行分段。",
  "highlights": [{ "quote": "玩家写的某几个字", "note": "对这一处的点评" }]
}
~~~

- **择字、辨字、拆篇**：品第由网页按得分给出，\`grade\` 不填。字是从盘里拣的，\`diffs\` 的反馈只有 hit / miss。辨字档看玩家在哪几处取了干扰字，讲清那个字与原字差在哪里——这就是「推」「敲」之辨；择字、拆篇档看哪些字放错了位置，从句法、对仗、平仄说说何以该在原处。全中也不必硬找话说，点一两处原作的用字即可。百字上下，\`highlights\` 一到三条。
- **填字**：品第由网页按得分给出，\`grade\` 不填。评点的重心在 \`diffs\`——玩家没填中的地方未必是错：他的字放在句中通不通、合不合律、与故事贴不贴？比原作强在哪、弱在哪？这正是「推」与「敲」的趣味所在。填中的妙处也点一两处。
- **补句**：网页会盖两方印。一方「合原」按得分自动给，只说明与原作相合了几个字；另一方「诗品」由你给，\`grade\` **要填**。诗品评的是玩家补出的句子本身：通不通、合不合律（\`prosody.issues\`）、与上下句和故事贴不贴、有没有自己的意思——**与是否撞上原作的字无关**。原作是你现写的，玩家无从背诵，整句补得与原作不同是常态：补得工稳贴切，诗品就该高；字字合原却全靠揭字，也不必高。评点仍从 \`diffs\` 谈起，方法同填字。
- **自赋**：由你定品，\`grade\` 取九品之一（上上、上中、上下、中上、中中、中下、下上、下中、下下），要给得诚实。从立意、意象、与故事的贴合、格律（\`prosody.issues\`）几面说；白卷或敷衍之作直说。
- 语气像一位爱诗的老先生：具体、恳切、有褒有贬，引玩家自己的字句来谈，不说空话。二百字上下，\`highlights\` 二到四条。
- 守住「别剧透」：玩家多半还没点揭晓。

送出评点后，在对话里告诉玩家评点已到、可以揭晓原作了；问他要不要再来一局。此后玩家若想聊原作（他已揭晓），就可以放开谈了。

## 其它命令

- \`tuiqiao list\`：已有的对局。\`tuiqiao status\` / \`start\` / \`stop\`：服务状态与起停。
- \`tuiqiao forms\`：常用体裁；\`--all\` 列全部，\`--kind shi|ci\` 筛选。
- \`tuiqiao char <字…>\`、\`tuiqiao rhymes [韵部] --rhymebook <韵书>\`：查字、查韵，见第二步。
- 体裁不在谱库里（古风、歌行、新诗等）：照常建局，\`form\` 写玩家说的名字；没有格律校验与平仄提示，\`check\` 可略过。
